# Web Energy Consumption Predictor

A web application that predicts household appliance energy use (in Wh) from indoor temperature and humidity readings, outdoor weather conditions and the time of day.

The model is trained on the [UCI Appliances Energy Prediction dataset](https://archive.ics.uci.edu/dataset/374/appliances+energy+prediction).

## Getting started

### 1. Clone the repository

```bash
git clone <repository-url>
cd Web-Energy-Consumption-Predictor
```

### 2. Create a virtual environment and install dependencies

```bash
python -m venv env
env\Scripts\activate          # Windows
# source env/bin/activate     # macOS / Linux
pip install -r requirements.txt
```

### 3. Download the dataset

Download `energydata_complete.csv` from the [UCI repository](https://archive.ics.uci.edu/dataset/374/appliances+energy+prediction) and place it in `data/raw/`.

### 4. Train the model

Open `notebook/full_process.ipynb` and run all cells. The notebook saves the trained pipeline to `artifacts/energy_model.joblib`.

## Machine learning pipeline

1. **Exploratory data analysis:** inspect shape, data types, missing values, duplicates, target distribution, and temperature, humidity and time patterns.
2. **Data cleaning:** convert `date` to datetime and check for missing values, duplicates and unusual readings. High energy readings are kept because they are genuine appliance usage.
3. **Feature engineering:** extract `hour`, `dayofweek` and `is_weekend` from the date. Drop `date` and the random noise columns `rv1` and `rv2`.
4. **Chronological split:** use the earliest 70% for training, the next 15% for validation and the latest 15% for testing. Data is not shuffled, so the model is always tested on future data.
5. **Model training:** compare Linear Regression (baseline), Random Forest Regressor and HistGradientBoostingRegressor, with hyperparameters tuned on the validation set.
6. **Evaluation:** report MAE, RMSE and R² on the validation set, then on the untouched test set.
7. **Overfitting check:** compare train, validation and test performance.
8. **Saving:** store the selected pipeline (preprocessing and model), the feature order and the metrics together in `artifacts/energy_model.joblib`.

## Limitations

- The data comes from a single house over about 4.5 months, so predictions may not generalise to other homes or seasons.
- Sudden high-usage spikes are hard to predict from environmental readings alone.
